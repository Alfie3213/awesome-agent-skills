## 详细介绍

### 1. [mvanhorn/last30days-skill](https://github.com/mvanhorn/last30days-skill)
一个面向深度研究场景的 AI Agent Skill。它能横跨 Reddit、X、YouTube、Hacker News、Bluesky、TikTok、Instagram、Polymarket 以及通用网页进行多平台检索，把近 30 天的碎片信息聚合成一份有据可查（grounded）的结构化总结。技术上以 Python 实现，强调时效性与"带引用"的输出，能直接挂载到 Claude Code、OpenClaw 等 Agent 环境中。本周新增超过 3,179 星，是榜单中增长最猛的 Skill 类项目。

**GitHub链接**：https://github.com/mvanhorn/last30days-skill

### 2. [ChromeDevTools/chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp)
由 Chrome DevTools 团队官方维护的 MCP Server，把浏览器调试能力完整暴露给编码 Agent。Agent 可以直接执行页面导航、抓取 DOM 与控制台日志、检查网络请求、分析性能指标并截图，从而自主定位前端 Bug。内部基于 Puppeteer 实现，支持本地与远程浏览器连接，是目前"让 Agent 真正看懂网页"的主流基础设施之一。

**GitHub链接**：https://github.com/ChromeDevTools/chrome-devtools-mcp

### 3. [alibaba/open-code-review](https://github.com/alibaba/open-code-review)
阿里巴巴开源的高性能 AI Code Review 工具，采用"确定性流水线 + LLM Agent"的混合架构：规则引擎负责可判定的逻辑缺陷（空指针、线程安全、XSS、SQL 注入等多语言规则集），大模型负责语义理解与上下文推理，最终输出精确到行级的评论意见。项目以 Go 编写，可扩展性强且在阿里内部大规模验证过，适合接入 CI 做自动化代码门禁。

**GitHub链接**：https://github.com/alibaba/open-code-review

### 4. [dream-num/univer](https://github.com/dream-num/univer)
Univer 是一套可二开的在线 Office 内核与 SDK，覆盖文档、表格、演示、PDF 等全部办公场景。它基于可扩展的开源核心构建，核心卖点是把编辑、计算、协作与文件处理能力同时开放给人和 AI Agent——也就是把"AI Office"作为一等公民来做，而不是事后贴一个聊天框。本周新增 7,248 星，是本次榜单中周增速最快的项目。

**GitHub链接**：https://github.com/dream-num/univer

### 5. [meta/astryx](https://github.com/meta/astryx)
Meta 开源的设计系统，主打"完全可定制"与"Agent Ready"。它不只是组件库，而是一套为 AI 生成界面准备的完整基础设施：设计 token、组件规范与文档都被整理成 Agent 可读、可复用的结构化形态，方便编码 Agent 直接按设计系统产出符合规范的 UI。适合在自研产品中快速搭建一致的前端体验。

**GitHub链接**：https://github.com/meta/astryx

## 趋势洞察

本周榜单透露出三个非常清晰的方向。

**第一，Agent Skills 已经从"个人玩票"进入"厂商级标准化"阶段。** 榜上同时出现 Google Labs 的 stitch-skills、Chrome 团队的 best-practices 知识库、以及多个社区自建的 Skill 包，且大多明确标注遵循 Agent Skills 开放标准、兼容 Claude Code / Cursor / Codex / Gemini CLI。这说明"Skill"正在形成类似 npm 包一样的跨 Agent 分发形态：写一次，处处可装。f封装、垂直化、共享化的 Skill 仓库，本周增量普遍在 2,000–3,500 星。

**第二，MCP 依然是 Agent 能力扩展的主干道。** chrome-devtools-mcp、ffmpeg-skill 都以 MCP Server 为核心交付形态，本周分别斩获 3,229 和 2,998 星。趋势在于：MCP 正从"能调用工具"走向"能操作复杂、长时间、多步骤的真实软件环境"——浏览器调试、本地视频剪辑这类过去必须人工完成的重活，正在被封装成 Agent 可直接驱动的标准接口。

**第三，"给人用的界面"和"给 Agent 用的界面"正在合流。** plannotator 把评审与反馈工作台化，ag-ui 给出 Agent 与前端交互的协议层，astryx 提供面向生成式 UI 的设计系统，univer 则把整套 Office 办公内核开放给 Agent 调用。四者指向同一件事：交互入口正从"聊天框"迁移到"有状态、有结构、可视化的工作空间"。当 Agent 的产出需要被人类监督、批注、签收时，UI 层就必须重新设计——而这一层的开源基础设施在本周明显开始加速补齐。

另一个值得留意的细节是"知识即上下文"的价值上升：Chrome 用一份结构化的 Web 规范文档就换来 6,858 星周增。对团队而言，相比换更大的模型，把领域知识整理成 Agent 可消费的结构化资产，可能是投入产出比更高的一步。
